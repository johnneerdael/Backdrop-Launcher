## Findings and decisions by category

| Category | Applied change | Preserved behavior and limits |
| --- | --- | --- |
| 1. State, snapshots and stability | Remove image measured-size/visibility snapshot state and bitmap-driven recomposition. Store these in a reusable artwork node and invalidate drawing on image delivery. Give context/selection-dependent remembered calculations explicit keys. Use an opaque remembered scene token instead of repeatedly hashing the complete scene for a composition key. Read animated scale once inside the graphics-layer update. | Keep standard list models and strong skipping; add no stability annotations, immutable collection wrappers, `computedStateOf` or new derivation machinery. Preserve source versioning and unchanged-return data reuse. |
| 2. Layout and measurement | Replace root `BoxWithConstraints` with a standard `Box` and a bottom-aligned 38% list height. Replace per-image `onGloballyPositioned` work with the exact 1.11.4 visibility-node API. Keep measured decode targets in the node, without a layout-to-composition feedback pass. Draw both scrims on the existing backdrop node instead of two decorative layout boxes. | Use the app-list bounds as the artwork viewport so rows clipped above the list remain excluded, even if their coordinates are inside the window. Preserve card dimensions, fixed Continue Watching placement and the same backdrop/scrim geometry. No intrinsic measurement or dynamic offset optimization is needed for fixed offsets. |
| 3. Lazy layouts | Supply both primitive semantic keys and content types for app rows and cards. Generate keys once per scene row collection, distinguish duplicate names/packages by occurrence, and avoid indexing identities as keys. Resolve density once above the lazy containers. | Keep real launcher rows/apps lazy, regardless of the small comparison fixture. Scene v1 has no persistent row/tile IDs; identical duplicate identities remain distinguishable by occurrence, not by a new schema guarantee. No linear index searches, shared polling flows or impression effects run in lazy items. Focus registration retains real disposal. |
| 4. Animation and transitions | Retain the 120ms Views-matched card focus animation, read only during graphics-layer updates, and immediate focus z-order. | Keep the 1.06 focus scale, pressed feedback and D-pad/Enter release activation. No shared transitions, per-frame composition size/offset reads or legacy `composed` animation modifiers were found in the candidate. Do not replace the existing small animation with a more elaborate node system without profiling evidence. |
| 5. Effects, lifecycle and threading | Add a frame suspension before dialog focus, rather than relying on synchronous `LaunchedEffect` timing. Cache the clock formatter/date holder and refresh it on resume and time/zone/locale changes; keep one active-screen receiver. Add a tested subscription generation gate so unchanged node bounds do not resubscribe and stale deliveries cannot repaint hidden/reused nodes. | Keep the bounded worker decoder and existing background data worker; no network/decode I/O moves onto the UI thread. Node detachment/reset and visibility exit release targets. Pause still cancels worker I/O and clears displayed images; resume revision still repairs coalesced pause/return. Per-card interaction flows are private in-memory UI interactions, not shared/external streams. |
| 6. Graphics and drawing | Use the same `BitmapPainter` scaling/alignment as Compose `Image`, with rectangular image clipping, directly in the artwork node. Cache both scrim brushes in `drawWithCache`. Replace generic pair-based focus lookup with primitive-packed coordinates and `LongSparseArray`. | Preserve asynchronous target-size hardware decoding, the 4 MiB reusable image cache, two workers, bounded queue, byte/deadline/path guards and original image/window resolution. The graphics reference explicitly permits asynchronous downsampling; replacing this decoder with Coil is unnecessary. Preserve hot-card alpha/fill/stroke and keep TV Material on other controls. |
| 7. Custom modifiers | Implement the image lifecycle/drawing with `ModifierNodeElement` plus a reusable `DelegatingNode`, draw/layout awareness and delegated visibility tracking. Update existing nodes, release/reset on reuse, and implement element equality through its configuration data class. | Use APIs verified in the exact Compose 1.11.4 source. Consume viewport changes within the visibility node, without observing bounds in composition. Add no `Modifier.composed`, repeated subcomposition or application-wide modifier framework. |

Every candidate composable was included: loading/error Home, the main screen, app cards, toolbar/Continue Watching/details surfaces, the clock, artwork and the Activity's composition entry point. The shared scene/provider/decoder contracts were inspected for compatibility and retained. Ordinary small toolbar/dialog rows remain eager layouts. No collection model annotations were added.

## Validation and next measurement

Three new regression assertions were observed failing against stub implementations, then passing after implementation: duplicate-safe identity after row/tile reordering, subscription deduplication with stale replacement deliveries, and cached image delivery with viewport exit/reentry. The Compose release suite now has 18 passing tests; release lint reports no errors and optimized assembly succeeds. A fresh reviewer checked all seven categories and the node/painter code against the exact dependency sources.

The new node changes the point at which asynchronous image work starts and draws. Source review cannot prove identical screenshots, steady CPU cost or a smaller GPU cache. Parent must compare populated fixed-content screenshots, normal and scrolled launch/return focus, Continue Watching cycling, details/settings return and repeated warm six-action navigation. Keep scene/source/APK identities, profile state and target order with each result. Reject foreground interference and account for transient graphics cache purges. Preserve full PSS/RSS/Swap/graphics/process-CPU denominators; do not optimize or infer adoption from one cache counter.

The earlier bounded-queue limitation remains: rejected image jobs retry only after their subscription changes. Confirm all visible artwork loaded before fixed-scene sampling. Production feature/data migration and any adoption decision remain separate gates.
